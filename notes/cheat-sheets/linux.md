<h2>Day 2 - users & permissions</h2>

<h3>Users and groups</h3>
  • кто я и в каких группах: `id`;
  • то же про другого пользователя: `id deploy`, `groups deploy`;
  • создать пользователя без пароля (вход только по ключу): `sudo adduser --disabled-password deploy`;
  • где записаны пользователи и группы: `/etc/passwd` (там же основная группа), `/ets/group`;
  • откуда берется содержимое новой домашней папки: `/etc/skel`

<h3>Permissions</h3>
  • права файла: `ls -l файл`, самой папки: `ls -ld папка`, со скрытыми файлами: `ls -la`;
  • как читать `-rwxr-x---`: первый символ - тип (`-` файл, `d` папка, `l` ссылка), дальше три тройки: владелец, группа, остальные;
  • права числами: r=4, w=2,x=1 → `700`=`rwx------`, `600` = `rw-------`, `755` = `rwx-xr-x`;
  • у папки: r - видеть имена, w - создавать и удалять, x - заходить;
  • сменить владельца и группу: `sudo chown deploy:deploy файл`;
  • сменить, только если сейчас владелец и группа root: `sudo chown --from root:root deploy:deploy файл`;
  • сменить права: `chmod 700 ~/.ssh`, `chmod 600 ~/.ssh/autorized_keys`;

<h3>sudo</h3>
  • что мне можно через sudo: `sudo -l`, что можно другому: `sudo -l -U deploy`;
  • полный путь к команде для правила: `which apt` → `/usr/bin/apt`;
  • правило - только через visudo, он проверяет синтаксис: `sudo visudo -f /etc/sudoers.d/deploy`
  ```console
  # разрешение для пользователя deploy на выполнение команды apt update без sudo
    deploy ALL=(root) NOPASSWD: /usr/bin/apt update
  ```
    формат: кто где=(от чьего имени) что; `%sudo` - вся группа sudo;

<h3>Problems and fixes</h3>
  • `Permission denied` → смотреть права в `ls -l`; 
    `Operation not permitted` → это может только владелец или root;
  • новый файл принадлежит тому, кто его создал: через `sudo` это root;
  • группа файла не обязана совпадать с группой владельца (`root adm`)
  • ловушки sudoers, которые молчат: `all` строчными (считается именем сервера), точка в имени файла в `sudoers.d` (файл пропускается), команда без аргументов (разрешены любые аргументы);
